# Reviewed SP11 kernel reconstruction

The experimental source is reconstructed incrementally on Linux stable
`v7.1.3`. The published stages preserve the conservative SP11/HID-over-SPI
prerequisite, reviewed camera branch, touch autoload, tablet-mode
resynchronization, charge-limit, camera-switch, DisplayPort DDC, and review20
suspend/deep-idle histories.

## Exact-history method

```sh
git clone https://git.kernel.org/pub/scm/linux/kernel/git/stable/linux.git linux
cd linux
git checkout v7.1.3
git fetch /path/to/sp11-alpha/kernel/sp11-sanitized2.bundle \
  refs/heads/sp11-sanitized2:refs/heads/sp11-sanitized2
git switch sp11-sanitized2
git rev-parse HEAD^{commit} HEAD^{tree}
```

The final command must print:

```text
2ace98eb6ef18cbd48074eed9f5b585d19ce398b
3924711c8ab3ee5c0208d214a4433eafc271df42
```

The bundle is intentionally incremental. It contains the complete sanitized
delta but requires base commit
`199c9959d3a9b53f346c221757fc7ac507fbac50` from Linux `v7.1.3`.

## End-state patch method

For a compact review or rebase:

```sh
git checkout v7.1.3
git apply --check /path/to/sp11-alpha/kernel/sp11-sanitized2.patch
git apply /path/to/sp11-alpha/kernel/sp11-sanitized2.patch
```

This reproduces the final files but not the curated 12-commit history.

## Configuration and build

Merge `kernel/config` with `kernel/camera-review.config.fragment` in the
out-of-tree build directory. The maintained helper performs that merge and
verifies the exact camera source identity:

```sh
./scripts/build-kernel.sh \
  --source /path/to/linux \
  --output /path/to/build \
  --jobs "$(nproc)"
```

See `BUILDINFO` and `docs/BUILD.md` for build and verification details.
`Module.symvers` is generated by a clean build and documents the matching
module ABI. Review20 keeps review12's functional configuration selections,
with
`CONFIG_DRM_MSM_VALIDATE_XML` normalized as explicitly disabled by
`olddefconfig` when using the pinned lxml build input. Its merged configuration
sets `CONFIG_LOCALVERSION=""`; the build helper's explicit
`KERNELRELEASE=7.1.3-sp11-suspend-review20` defines the authoritative release
identity.
It also requires the declared Python 3.14.6 and lxml 6.1.1 versions used for
the qualified builds.

Review20 adds no exported symbol, so its `Module.symvers` remains
byte-identical to review12's.

## Touch SPI autoload correction

`sp11-touch-spi-autoload.bundle` adds one commit on top of the exact camera
tip. Review4 exposed the touchscreen as `spi:g6-touch-digitizer`, but its
`spi_hid_of` module advertised only `spi:microsoft,g6-touch-digitizer`; udev
therefore could not autoload the driver. Explicitly loading the module restored
the physical touchscreen/stylus and both iptsd virtual devices. The correction
restores the SPI ID used by the actual modalias without changing the DTB.

## Tablet-mode resume resynchronization

`sp11-tablet-mode-resume-resync.bundle` adds three commits on top of the exact
touch-autoload tip. The Surface Aggregator tablet-mode switch queries the
controller immediately on resume, then queries it once more after two seconds.
It also uses the KIP connection event to query every two seconds for a bounded
30-second settling window when the Flex Keyboard is attached or detached.
Transient values outside the valid posture range are not cached, and the
sequence stops on the first valid controller response. Each path reports a new
input state only when the controller itself says that the posture changed.

```sh
git fetch /path/to/sp11-alpha/kernel/sp11-tablet-mode-resume-resync.bundle \
```

## Rear camera switch reliability

`sp11-camera-switch-fix.bundle` adds one commit on top of the exact
charge-limit reliability tip. The rear OV13858's first SCCB transaction after
power-up intermittently returned `-EIO` behind a CCI queue timeout whenever
another camera on the same SoC had been active shortly beforehand, leaving the
sensor unable to start streaming. The correction retries that single idempotent
software-reset write once. It is scoped to that register only; the later writes
in the streaming sequence are not idempotent and are unchanged.

```sh
git fetch /path/to/sp11-alpha/kernel/sp11-camera-switch-fix.bundle \
  refs/heads/integration/review10-camera-switch:refs/heads/integration/review10-camera-switch
git switch integration/review10-camera-switch
```

```text

c30f01a3d05a28bf8c4a0e809fc8f81a919927af
```

For patch review, apply `sp11-camera-switch-fix.patch` to the exact

## DisplayPort DDC/CI

`sp11-dp-ddc-fix.bundle` adds two commits on top of the exact camera-switch
tip, both correcting upstream `drivers/gpu/drm/msm/dp/` behaviour that prevents
DDC/CI from working on an external DisplayPort monitor.

The first restricts `msm_dp_aux_transfer_helper()` to the EDID and segment
addresses. That helper is a workaround for sinks that mishandle the I2C
middle-of-transaction flag during EDID reads, but it checked no address, so it
accumulated an EDID read offset on unrelated I2C-over-AUX traffic and injected
that offset back as a one-byte write to whatever device was being addressed.
DDC/CI at 0x37 was corrupted as a result; EDID reads at 0x50 were unaffected,
which is why the fault looked like an unresponsive monitor.

The second sets `drm_bridge.ddc` to the AUX i2c adapter that
`drm_dp_aux_register()` already creates, so `drm_bridge_connector_init()`
attaches it to the connector and `/sys/class/drm/<connector>/ddc` exists.
Without that link userspace cannot map a display to its i2c bus.

```sh
git fetch /path/to/sp11-alpha/kernel/sp11-dp-ddc-fix.bundle \
  refs/heads/integration/review12-dp-ddc:refs/heads/integration/review12-dp-ddc
git switch integration/review12-dp-ddc
git rev-parse HEAD^{commit} HEAD^{tree}
```

The final command must print:

```text
a3e71f7080ee40dccfdd9500b8957a7c143fb6a2
a1704b98847e95fe6c26c57ce5a588faec011924
```

For patch review, apply `sp11-dp-ddc-fix.patch` to the exact camera-switch tip.

## Half-screen colour tint after resume or DPMS (DSPP gamma LUT)

`sp11-dpu-gc-lut-after-modeset.patch` fixes a random colour tint with
artifacts on one half of the internal panel after every suspend/resume or
DPMS off/on whenever a compositor applies a `GAMMA_LUT` (for example Hyprland
with wlsunset). On a modeset the DPU driver programs the DSPP gamma (GC) LUT
before the first flush has activated the block: the enable bit sticks but the
SRAM LUT writes are lost, so gamma runs over uninitialised memory until the
next colour-management commit. The patch repeats the colour-processing
programming on the commit after a modeset.

Register evidence and the verification (DPMS off/on 10/10 clean, previously
defective every cycle) are in the commit message. The change touches only
`drivers/gpu/drm/msm/disp/dpu1/dpu_crtc.{c,h}` and needs no configuration
change.

This patch was developed and verified on the local 7.3 port branch
(`port/sp11-7.3`, commit `a2c103f964eb9cc9a6799b567d81357504a62d3a`); it has
been checked to apply cleanly with `git apply --check` to the exact review20
tip `18d7951a10dc49e383d16c6af82fc2c07784de3d`, but no reproducible 7.1.3
build including it has been published yet, so it ships as a patch only, with
no bundle. It is also a candidate for upstream `drm/msm`, since the GC LUT
support it corrects is upstream code.
